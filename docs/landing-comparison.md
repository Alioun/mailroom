# Saved placement comparison

Opening a saved account recomputes a local comparison of observed folders and the last recorded composed deployment. Reopening after a census refresh uses the refreshed saved records. The report does not acquire mail or change rules, flags, messages, approvals or provider authority.

The baseline requires all of the following evidence:

- The newest recorded transaction is a complete version-2 composed deploy with an active target.
- Its final effect was observed and matches its exact recorded after-image.
- The deployment record retains the identical immutable compiled artifact for that account and engine, with current compiler and proof semantics. Older deployments can use an exact matching export as a legacy fallback.
- Recomposing that artifact with the recorded existing rules reproduces the exact recorded host and included script bytes.
- A completed census refresh supplies the comparison date.

A download alone supplies no deployment evidence. Missing artifacts never fall back to the current editable rules. Historical version-1 order, removal, compensation, unresolved transactions, changed bytes and unavailable evaluation return separate unavailable reasons. An unavailable comparison changes no transaction state.

The evaluator runs the retained executable over saved received messages. Existing-rule filing takes priority through the same composition evaluator used by deployment proof. Each row shows observed folders and either a predicted folder or an explicit uncertainty. Folder matches, observations elsewhere and additional observed folders have separate counts. Unknown recipient authority, undecidable existing rules and non-folder actions are uncheckable. A discard or redirect does not become a missing-folder failure.

The report binds its account, census SHA-256, last completed refresh, recorded transaction and artifact. Incomplete acquisition and restored historical data remain visible. The local English/German panel shows 50 rows per page. Client parsing checks known semantics, row variants, account association and count agreement. Details stay in the protected account view and do not enter agent summaries.

This is a comparison of recorded snapshots. It includes old messages and later moves. It does not establish the initial delivery destination, causation, continued script activation, accounting-copy receipt, keyword persistence or complete provider coverage. Excluded folders remain outside the saved message set. Partial scans can mix observations from different times.

State schema 30 retains the exact approved artifact with each new composed deployment intent in one encrypted account save before effects. Preview keeps the compiled artifact internal, and confirmation rechecks the existing receipt and freshness conditions before saving. Removing a deployment or compensating it creates no replacement artifact. Encrypted reopen, key rotation and both recovery formats preserve these records. Restored accounts keep their execution hold.

The dedicated records survive export eviction, and deployment requires no prior download. The report identifies whether a dedicated record or a legacy export supplies its baseline. Missing material makes comparison unavailable and never triggers recompilation. The transaction journal admits at most 64 operations under schema 32 and refuses when its count or byte budget is full. Artifact retention follows the same count bound and never silently prunes history. Exact activation time remains unknown. The separate mailbox-date interval below uses an observed active image.

Credential-free verification uses constructed recorded deployments, real compiled artifacts and encrypted reopen, followed by actual account Router/client checks and bilingual server rendering. These checks do not establish mounted interaction, visual, connected, provider or whole-workflow acceptance.


## Mailbox dates after an active observation

Schema 31 adds the first recorded observation time of the exact active image to the retained artifact. A successful final readback saves it with transaction completion. Read-only reconciliation can record it when the final image is first confirmed later. The record identifies which path supplied the time. Later observations preserve the first timestamp. Missing historical timing stays unavailable and is never inferred from download time.

The complete comparison remains unchanged. A separate interval includes received rows whose IMAP INTERNALDATE is strictly after the observation and no later than the last completed census refresh. It uses the existing full-census proof and precedence results. Header Date never determines membership. Equal or older mailbox dates, invalid or missing INTERNALDATE and dates after the refresh remain outside the interval with explicit row labels. A refresh predating the observation leaves the interval unavailable.

The local panel shows the exact interval, separate counts and a filter for its rows. It distinguishes an empty interval from an empty saved census. Both recovery forms and key rotation preserve timing with the artifact. Restored results remain historical and cannot resume effects.

These times compare the local observation clock with provider-supplied mailbox dates. Copying and importing can preserve or assign INTERNALDATE. Clock disagreement can exclude messages or put them outside the interval. This is neither proof of SMTP arrival nor the initial destination. Reconciliation records its later observation time, never the original activation time. Continuous activation, copy receipt, keyword persistence and complete provider coverage remain unverified.
