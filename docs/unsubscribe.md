# Exact subscription unsubscribe and mute tests

The local interface provides synthetic test controls for exact account, receiving-address and List-Id subscriptions. One review groups subscriptions visually by sender across census accounts. Sender groups rank by their separate subscriptions' combined 12-month unread volume, descending, with sender names breaking ties. Child subscriptions rank by unread volume, then exact account/subscription key. Expandable sender groups show the number of separate subscriptions, with no sender-wide approval checkbox. Each account, receiving address and mailing list has its own checkbox and method. Eligible subscriptions are initially checked, and a single exact list confirmation binds every selected identity. Q20 settles product scope only; all real operations remain denied.

## Candidate facts

The report reuses census classification and the pinned PSL. It keeps distinct receiving addresses and List-Ids separate, ranks by unread 12-month volume, and uses a stable subscription identifier to break ties. People lists, platform senders, unknown flags, partial census, unresolved recipients and missing relay originals prevent recommendations. The five-message and six-calendar-month boundaries are inclusive. A Seen message's Date is a message date, not an observed read time.

Account-state version 5 adds encrypted unsubscribe history and owned mute overrides. Versions 1 through 4 migrate without invented approvals or flag coverage. Each message now records whether its flags were observed. A metadata refresh supplies that evidence. The report displays the last complete census time and its age when available, without inventing a freshness threshold. Existing census, workspace, export, backlog and invoice writers preserve the aggregate.

## Method authority and effects

Ordinary parsed Authentication-Results and DKIM headers remain unknown. Only the installed synthetic provider fixture can correlate a passing signature with both exact unsubscribe headers. Caller JSON cannot install provider trust or transport adapters.

The automatic method parses HTTPS conservatively, rejects credentials and ambiguous authorities, checks every DNS answer for nonpublic IPv4/IPv6 destinations, binds the checked peer addresses, and refuses redirects. The installed fake fixture resolves only its designated host to a canned public address.

`unsubscribe::one_click` is the native adapter. It resolves the host once, refuses the whole request when any answer is loopback, private, link-local or otherwise nonpublic, connects to a checked address, verifies the certificate for the host and writes one `POST` of `List-Unsubscribe=One-Click`. A 3xx status is recorded and its Location is never followed. A failure before the request is written records `not_sent`; a missing status after it records `uncertain`. History keeps the status code and the URI host. Tests run it against local TLS fakes through a fixture resolver.

Optional local unsubscribe mail goes through the SMTP adapter described in `docs/invoices.md`. The message carries the previewed target, receiving address, subject and body, with framing fixed by the review time `as_of`. On the wired route the confirmation names the SHA-256 of exactly those bytes, and submission rebuilds and compares them before sending. The accepted outcome is `submitted`. The mail-app path never opens the default `mailto:` handler: Finder opens Apple Mail, which composes a new message with the parsed target, subject and body from the receiving address, and closes the draft unsaved and fails when Mail does not take that sender. It records `handed_off`, never sent. A `mailto:` link with a literal `#` is refused. Both the per-account route and the combined subscription review use these guarded adapters, including when a test installs fake endpoints; the fixture server otherwise keeps its synthetic adapter. The confirmation boundary names them as `one_click_post`, `smtp_send` and `mail_app_handoff`. Each wired action needs a `policy::WritePermit` first, which `policy::authorize` denies, so production answers 403 before any repository or network access. `resolve` records the owner's finding for an uncertain local unsubscribe message as `sent` (`submitted`) or `not_sent`, and never resends. The combined review preflights endpoints for every selected account before saving any intents and uses the same executor as the per-account route. The UI takes review availability from the server. Descriptive synthetic confirmation metadata does not authorize an action.

On the wired route one-click authority comes from the census's recorded provider evidence (`unsubscribe::authority`). The topmost Authentication-Results header must carry the provider's authserv-id, no other header may claim it, a `dkim=pass` result there must name the message's DKIM-Signature by `header.d` (and `header.s` and a `header.b` prefix where recorded), and every signature it names must cover both List-Unsubscribe and List-Unsubscribe-Post, each present exactly once. Gmail's authserv-id is `mx.google.com`. mailbox.org's is not yet established, so its mail offers no one-click POST. Anything missing or unknown offers none.

A fake POST uses exactly `List-Unsubscribe=One-Click` with form content type, without cookies, referrer or unrelated headers. A mailto copy card contains the exact recipient, receiving identity, subject and body. Its synthetic local send needs an additional action-naming confirmation. The checkbox is a simulation, not an OS dialog or passkey prompt. In the installed synthetic fixture, browser, mail-app and address-retirement actions are preparation only and launch nothing. The wired mail-app path uses the confirmed handoff described above.

A dedicated full HMAC binds state, census, workspace revision, exact subscriptions, source/header digests, methods, hosts, roles, destinations, displayed effects and compiled proof. The server recomputes the preview before accepting confirmation. Invoice and proof-download receipts cannot authorize unsubscribe.

Intent precedes an independently encrypted fake effect. Observation follows it. Recovery reconciles matching acknowledgments; an absent acknowledgment stays uncertain and blocks a new action without retry. HTTP status, mail handoff and actual unsubscribe success remain separate. Success stays unknown. External unsubscribe has no Undo.

History and independent acknowledgment records contain hosts and opaque digests, never token-bearing URIs or mail bodies. Transient exact copy cards stay in protected responses and component memory. Browser storage is unused. The encrypted original census retains original headers.

## Mutes

A mute creates an owned `user.mute.*` override. It matches the full List-Id header with Sieve `header :is` and ASCII casemap semantics, or exact From with a List-Id-absent guard when List-Id is absent. It also restricts the receiving address and account. It never substitutes a domain match. Duplicate List-Id evidence remains a distinct ambiguous subscription and prevents mute availability. Gmail observations combine Seen flags. Pin conflicts block confirmation.

The folder segment is configurable for each role and sits beneath the configured role root. Mutes mark future messages read. Recipient safety and guards retain precedence; invoice copies remain independent before filing. Missing flag capability omits the entire read-marking rule. Production deployment and retroactive movement/read marking remain unavailable.

Mute writes preserve unrelated configuration semantics but serialize the override document canonically. YAML comments and original formatting are not preserved. Removal previews the compiled rules without the unchanged owned override. A changed rule or patch causes rejection so user edits survive. Removing the rule changes future routing only. A later census proposes mute only after 14 days, an observed request or mail handoff, and a new source with an arrival after the request. Refreshing old mail does not qualify. Missing observation or arrival evidence stays unknown.

- `./scripts/verify-sieve.sh` compares emitted Sieve with independent check-sieve and Pigeonhole executions. Fresh-cache cases do not establish persistent provider cache behavior.

- `scripts/verify-unsubscribe.mjs` exercises protected HTTP for synthetic IMAP and Gmail.
- `ui/scripts/verify-unsubscribe-ranking.mjs` checks built sender and child ordering with alphabetical input, cross-account totals, ties and unchanged selection eligibility. It requires two existing synthetic census accounts and makes no effects.
- `ui/scripts/verify-unsubscribe.mjs` drives the built English/German interface and records local synthetic screenshots.
