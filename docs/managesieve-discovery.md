# Private ManageSieve discovery

The production library contains a private RFC 5804 read session. Only a test constructor installs a resolved loopback socket, separate expected TLS identity, trust root and source epoch. Ordinary synthetic mode grants no endpoint authority. All production ManageSieve HTTP requests reject before repository, credential or network access. DNS/service discovery, production endpoints, implicit TLS and other authentication profiles are unsupported.

The session consumes greeting capabilities through terminal OK, requires STARTTLS, verifies the chain and reference identity with native TLS, discards plaintext advertisements and consumes new TLS advertisements. It attempts PLAIN once, without a SASL security layer, then explicitly requests authenticated CAPABILITY. It exposes only capability/list/get and bounded logout operations. There is no raw command, referral following, retry, plaintext fallback or write adapter.

Framing counts literal octets across arbitrary reads. Returned scripts retain their exact bytes and SHA-256, including invalid UTF-8. Quoted strings are limited to 1024 bytes. Capabilities and lists each have a 64 KiB response budget and at most 256 entries. A fetched script is limited to 1 MiB. The attempt budget is 4 MiB including repeated reads and framing. Two maximum-sized bodies fetched twice exceed that total and fail explicitly. Limits never truncate a successful baseline. Connect uses a resolved address and a 250 ms timeout. Handshake/command deadlines are at most 15 seconds; the whole session is at most 60 seconds. Nonblocking IO checks cancellation and absolute deadlines between polls. Storage/credential backend operations use the existing local synchronous interfaces.

Discovery records an encrypted running attempt before password retrieval/connect. Authenticated capabilities, complete returned names and required body checkpoints remain distinct. It fetches the active script and Open-Xchange if present and distinct, then repeats authenticated capabilities, list and required reads. Any disagreement fails as unstable and preserves the old success. NO, missing bodies, partial lists, EOF and BYE cannot become empty success. Unknown status text is discarded and has no machine authority.

Matching reads are observations, not a server transaction. They cannot exclude change-and-revert. Include dependencies are uncaptured. No deployment or compiler trust follows from advertisements. Saved-account proof retains its conservative recipient authority.

The versioned facts live inside the complete encrypted AccountState. Internal schema 10 advances store and single/selected recovery readers and the browser manifest validator together. Schemas 1 through 9 read without invented Sieve facts and reject new semantics under old schemas. Existing recovery account-count/resource limits and envelope versions remain. Oversized capture fails without pruning observations. On reopen running becomes interrupted. The last success remains separate. New/failed attempts, source changes, password reference changes, rotation and restoration invalidate currentness. Source identity includes resolved endpoint, trust root, expected name and epoch. Key and recovery authority are bound independently. Age is displayed without a freshness policy.

The protected account endpoint accepts only an account and open/start/cancel/status action. Discovery uses the existing admission, operation, worker, lifecycle and account/store locks. Lifecycle cancellation joins the discovery worker. Every checkpoint reloads/checks revision through existing encrypted aggregate persistence. Recovery holds block refresh and any saved-state mutation.

English/German local controls display partial attempts, failures, current/historical success, authenticated advertisements, complete names/active status and byte/digest review. UTF-8 is decoded strictly; hex review always preserves exact bytes. Script text is escaped by Svelte interpolation. The UI uses no browser storage or remote requests and exposes no deployment control.

Run the Rust tests and `node scripts/verify-managesieve-discovery.mjs`, then `node ui/scripts/verify-managesieve-discovery.mjs` against its retained fake. The runtime receipt records exactly which cases ran. Adapter tests are not an independent Sieve-engine execution. Docker/Pigeonhole remains blocked by unavailable infrastructure and must not be provisioned for this unit. Native trust, protected Keychain, actual providers, coexistence/composition, provisioning and daily readiness remain unverified.

Name validation also rejects Unicode line/paragraph separators, an initial BOM and unassigned code points using the existing locked ICU data table. Quoted strings require valid UTF-8 and count escape bytes on the wire. Literal script contents retain arbitrary octets. Post-TLS STARTTLS advertisements reject before authentication.
