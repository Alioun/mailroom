# Synthetic IMAP folder provisioning

The create-only transport uses verified implicit TLS and a separately installed, account-bound loopback source. Production and ordinary read installations cannot obtain its private create permit. The transport sends CAPABILITY, one LOGIN, NAMESPACE, complete LIST, exact CREATE and bounded LOGOUT. It performs no DNS lookup or plaintext fallback.

The version-one mapping requires IMAP4rev1, NAMESPACE, one observed empty personal prefix and slash hierarchy. UTF8=ONLY, IMAP4rev2, ambiguous personal namespaces, namespace extensions and incompatible topology reject. Optional UTF8=ACCEPT remains unenabled. Client names use quoted canonical modified UTF-7. Server quoted strings, atoms and fragmented octet-counted literals are bounded. Non-NFC text, combining sequences and Hangul Jamo are explicitly unsupported. No normalization changes an owner's text.

The saved immutable artifact supplies every candidate destination through `CompiledArtifact::folders()`. Required ancestors appear separately and in depth order. Existing selectable leaves require no CREATE. Nonselectable ancestors may be containers, but nonselectable leaves and ancestors forbidding children reject. Wildcards are compared locally against the complete inventory.

Ordinary saved-workspace compilation uses unknown recipient evidence and empty capabilities, so its artifact has no folder candidates. Explicit test-only fixture construction can install an account-bound `SyntheticWorkspaceAuthority` with an identity, epoch, profile, recipient evidence and exact capability set. Transport capabilities and headers cannot install this authority. One bound `WorkspaceContext` drives saved validation, proof, confirmed downloads, export baselines, proposals, ledger changes and folder planning. The HTTP and built-browser verifiers save invented multi-folder rules and confirm actual TLS CREATE against those same artifacts. Production compilation remains conservative.

A purpose-separated receipt binds complete primary state, source, account, credential generation, key and recovery authority, proof, exact plan, wire names and observed topology. Approval is consumed before command intents. Each intent precedes CREATE. Acknowledgment and complete fresh LIST readback remain separate. An interrupted intent is uncertain. Status never resumes work. Reconciliation issues only observations and requires renewed exact review after absence or incomplete work. Matching visible state proves neither attribution nor historical non-occurrence.

The primary journal uses internal schema 13. Schema 12 introduced folder journals and fake topology. Schema 13 binds export usability to the installed workspace context. Older exports load without a binding and are unusable. Older schemas reject injected bindings. Single and selected recovery accept schemas through 13 and retain read-only holds. The independent fake TLS identity, topology and safe command names live in the existing encrypted mailbox resource. Primary restoration cannot roll back later fake folder effects.

Every command's response has its own deadline, at most 10 s, which starts when the client waits for it. The session's overall deadline starts at the installed operation budget, at most 60 s, and each completed command extends it by 5 s. Time the session sits idle between flights, while the client does local work, is added back, so the overall deadline bounds time spent waiting on the server. A plan of any size can finish while the server averages under 5 s per command, and Cancel is checked while waiting on every byte. The same session policy applies to the synthetic MOVE and Gmail label transports.

The transport pipelines read-only checks (RFC 3501 section 5.5). Topology observation (CAPABILITY, NAMESPACE, LIST, NAMESPACE, CAPABILITY) is one flight. A MOVE's checks (topology, the destination's identity, the sources' exact state and the source selected again) are one flight, and the MOVE leaves only after every response passed. A Gmail label STORE waits for its topology and member checks the same way. No command is ever pipelined behind an effect. Steps of one check stand or fall together: once a SELECT fails, the rows after it are read past and never attributed. A MOVE or Gmail confirm runs over the session its preview opened, and a preview keeps that session open while a second, read-only session reads the folders. Journal saves inside the session append small frames instead of rewriting the census.

CREATE has no compare-and-swap. A server may recreate a parent removed after the last LIST, or subscribe a new mailbox itself. Complete observations reduce stale plans without excluding that race. The application sends no SUBSCRIBE, DELETE, RENAME, compensation, message mutation or Sieve deployment.

Folder and Gmail label histories explain every recorded creation failure in English and German. Their shared client parser accepts only the recorded failure variants. Saved intent does not establish that CREATE was sent. An explanation does not establish whether an interrupted CREATE reached the server; the step outcome, acknowledgment and observed inventory remain separate evidence. Unknown diagnostic codes fail parsing rather than appearing as unexplained text.

Actual provider namespaces, permissions, quotas, name equivalence, implicit parent and subscription behavior, Sieve mapping and delivery remain unverified. Native confirmation and personal readiness remain outside this unit.
